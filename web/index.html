Laboratorio #1: Almacenamiento y Validación XML en Oracle

Entorno interactivo de simulación y herramientas para el desarrollo de actividades.

Objetivos del Laboratorio

Este laboratorio práctico tiene como objetivo aplicar conocimientos sobre bases de datos XML nativas e híbridas en el SGBD Oracle 11g. Las actividades están divididas en 4 partes fundamentales:

1

Consulta SQL/XML

Generación de estructuras XML a partir de tablas relacionales de la base de datos de ejemplo (esquema HR) uniendo EMPLOYEES y DEPARTMENTS.

2

Esquema XML (XSD)

Construcción y modelado de un esquema XSD que defina y valide la estructura exacta de los datos XML generados en la consulta.

3

Validación

Validación interactiva del archivo XML recuperado comparándolo contra las reglas y restricciones del esquema XSD diseñado.

4

Oracle XML DB

Registro lógico del esquema mediante PL/SQL, creación de tablas tipadas XMLTYPE e inserción de datos correctos y erróneos para verificar la validación en el motor.

Requisitos del Entorno

  • Motor BD: Oracle Database (11g o superior) con esquema de prueba HR activado.
  • Cliente SQL: Oracle SQL Developer para ejecutar comandos y consultas.
  • Soporte XML DB: Activación y permisos sobre paquetes como DBMS_XMLSCHEMA.

Entregables Requeridos

  • Código Fuente: Ficheros SQL estructurados con consultas, registro e inserciones.
  • Memoria de Práctica: Explicación de los pasos, justificación técnica del código y capturas del proceso. Puedes generar un borrador en la última sección de esta web.

Paso 2: Esquema XML de Validación (XSD)

Estructura formal que rige la conformación del documento XML para garantizar la calidad de la información.

Definición del Archivo XSD (schema.xsd)

Estructura Jerárquica del Esquema (7 Tablas)

  • Corporacion (Raíz, ComplexType)
    • Regiones (Secuencia)
      • Region (maxOccurs: unbounded, Atrib: id, nombre)
        • Paises (minOccurs: 0)
          • Pais (maxOccurs: unbounded, Atrib: id, nombre)
            • Localizaciones (minOccurs: 0)
              • Localizacion (maxOccurs: unbounded, Atrib: id)
                • Direccion (xs:string)
                • CodigoPostal (xs:string)
                • Ciudad (xs:string)
                • Provincia (xs:string)
                • Departamentos (minOccurs: 0)
                  • Departamento (maxOccurs: unbounded, Atrib: id, nombre)
                    • Empleados (minOccurs: 0)
                      • Empleado (maxOccurs: unbounded, Atrib: id)
                        • Nombre (xs:string)
                        • Apellido (xs:string)
                        • Correo (xs:string)
                        • Telefono (xs:string)
                        • FechaContratacion (xs:date)
                        • Salario (xs:decimal)
                        • Comision (xs:decimal)
                        • TrabajoActual (Atrib: id, titulo)
                          • SalarioMinimo (xs:decimal)
                          • SalarioMaximo (xs:decimal)
                        • HistorialLaboral (minOccurs: 0)
                          • Historial (maxOccurs: unbounded)
                            • FechaInicio (xs:date)
                            • FechaFin (xs:date)
                            • IdTrabajo (xs:string)
                            • IdDepartamento (xs:integer)

Reglas de Validación Clave (7 Niveles)

  • Integridad de Fechas: Elementos como FechaContratacion, FechaInicio y FechaFin deben seguir el formato ISO de fecha (xs:date: YYYY-MM-DD).
  • Atributos Requeridos: Atributo id es obligatorio en los elementos de Región, País, Localización, Departamento, Empleado y Trabajo.
  • Restricciones de Tipos: El atributo id de País y Trabajo es de tipo cadena (`xs:string`), mientras que el resto de IDs son enteros (`xs:integer`). Los salarios y comisiones deben ser decimales (`xs:decimal`).
